## 학습 목표

1. `IPointerDownHandler` 같은 포인터 이벤트 인터페이스가 "버튼 위에서 마우스가 무엇을 했는지"를 스크립트에 알려 준다는 것을 설명할 수 있다.
2. `Awake()` 에서 원래 크기를 기억해 두고, 눌림·놓음·벗어남 모두 원래 크기로 돌아오게 만들 수 있다.
3. `DOShakeAnchorPos` 의 인자와 `SetLoops(-1, LoopType.Yoyo)` 를 읽고 값을 바꿔 다른 느낌을 낼 수 있다.

## 개념 설명

### 1. 용어

| 용어 | 한 줄 풀이 |
|---|---|
| 포인터 (Pointer) | 마우스 커서나 손가락 터치를 함께 부르는 말 |
| 인터페이스 (Interface) | "이 함수를 꼭 갖고 있겠다"는 약속. `IPointerDownHandler` 를 붙이면 `OnPointerDown` 을 만들어야 한다 |
| EventSystem | 마우스·터치가 어느 UI 위에 있는지 찾아 알려 주는 오브젝트. 씬마다 하나 |
| `InputSystemUIInputModule` | 이 프로젝트의 EventSystem 입력 모듈. 프로젝트가 Input System 전용이라 이것을 쓴다 (`docs/scene-builder.md`) |
| Raycast Target | Image·Text 의 체크 칸. 꺼져 있으면 마우스가 그 UI 를 "못 본다" |
| `localScale` | 자기 크기 배율. 1 = 원래 크기 |
| Mask | 자식 UI 를 자기 모양 안쪽만 보이게 자르는 컴포넌트 |
| Yoyo | 갔다가 되돌아오는 반복. 1 → 1.15 → 1 → 1.15 … |

### 2. 포인터 이벤트 다섯 개

| 인터페이스 | 불리는 함수 | 언제 | 쓴 용어 |
|---|---|---|---|
| `IPointerDownHandler` | `OnPointerDown` | 버튼 위에서 누른 순간 | 0201, 0203 |
| `IPointerUpHandler` | `OnPointerUp` | 누른 뒤 뗀 순간 | 0201 |
| `IPointerEnterHandler` | `OnPointerEnter` | 커서가 들어온 순간 | 0202 |
| `IPointerExitHandler` | `OnPointerExit` | 커서가 나간 순간 | 0201, 0202 |
| (Button 의) `On Click ()` | 인스펙터에 연결한 함수 | 누르고 **같은 버튼 위에서** 뗐을 때 | 0204 |

`ButtonPressEffect.cs` 5행 (찾을 글자: `public class ButtonPressEffect`)

```csharp
public class ButtonPressEffect : MonoBehaviour, IPointerDownHandler, IPointerUpHandler, IPointerExitHandler
```

- 클래스 이름 뒤 `,` 로 인터페이스를 이어 붙입니다. `using UnityEngine.EventSystems;` 가 있어야 합니다 (2행).
- 이벤트가 오려면 세 가지가 필요합니다: ① 씬에 EventSystem ② 그 오브젝트(또는 자식)에 **Raycast Target** 이 켜진 Graphic ③ 위를 덮는 다른 UI 가 없을 것.

### 3. 원래 크기 기억하기 — 0201·0202

`ButtonPressEffect.cs` 10–37행

```csharp
private Vector3 originalScale;

private void Awake()
{
    originalScale = transform.localScale;
}

public void OnPointerDown(PointerEventData eventData)
{
    transform.DOKill();
    transform.DOScale(originalScale * pressedScale, duration)   // 0.9배, 0.1초
        .SetEase(Ease.OutQuad);
}

public void OnPointerUp(PointerEventData eventData)
{
    transform.DOKill();
    transform.DOScale(originalScale, duration)
        .SetEase(Ease.OutBack); // 놓을 때 살짝 튕기며 복귀
}
```

- `1` 이 아니라 `originalScale` 로 돌아갑니다. 버튼 크기를 1.2 로 놓아 두었어도 망가지지 않습니다.
- `OnPointerExit` 도 같은 복귀를 합니다 (31–37행). 누른 채 밖으로 나가면 `OnPointerUp` 만 믿을 수 없기 때문입니다 (주석: "누른 상태에서 버튼 영역 밖으로 … 벗어나도 원래 크기로 복귀").

| 용어 | 값 | 기본값 |
|---|---|---|
| 0201 `ButtonPressEffect` | `pressedScale` / `duration` | 0.9 / 0.1 |
| 0202 `ButtonHoverHighlight` | `hoverScale` / `duration` / `hoverColor` | 1.08 / 0.2 / (1, 0.85, 0.4) 노란빛 |

**0202 의 색**: `ButtonHoverHighlight.cs` 29–33행은 `if (targetImage != null)` 안에서만 `DOColor` 를 합니다. `11_ButtonHover` 씬은 **Target Image** 가 비어 있어서 크기만 바뀝니다. 빈 칸이어도 오류가 나지 않게 `null` 을 먼저 확인한 코드입니다.

### 4. 누른 자리에서 퍼지기 — 0203

[그림: 화면 좌표(픽셀, 왼쪽 아래 0,0) → RippleMask 안 로컬 좌표(가운데 0,0)로 바뀌는 화살표. 클릭 점이 RippleCircle 의 anchoredPosition 이 됨]

`ButtonRipple.cs` 14–37행 (찾을 글자: `ScreenPointToLocalPointInRectangle`)

```csharp
RectTransformUtility.ScreenPointToLocalPointInRectangle(
    rippleCircle.parent as RectTransform,   // 기준: 리플 원의 부모(RippleMask)
    eventData.position,                     // 클릭한 화면 좌표 (픽셀)
    eventData.pressEventCamera,             // Overlay 캔버스면 null
    out Vector2 localPoint
);
rippleCircle.anchoredPosition = localPoint;
rippleCircle.localScale = Vector3.zero;
rippleImage.color = rippleColor;            // 반투명 흰색 (a 0.4)

rippleCircle.DOScale(maxScale, duration).SetEase(Ease.OutQuad);   // 15배로 커지고
rippleImage.DOFade(0f, duration).SetEase(Ease.OutQuad);           // 동시에 사라짐
```

- 화면 좌표(픽셀)를 "부모 안 좌표"로 바꿔야 그 자리에 원을 놓을 수 있습니다. 40번 물결 왜곡도 같은 변환을 씁니다 (`docs/shader/40-wave-distortion.md`).
- 원이 버튼보다 커져도 `RippleMask`(Mask 컴포넌트) 안쪽만 보입니다.

### 5. 흔들림 인자 읽기 — 0204

`ShakeEffect.cs` 12–26행

```csharp
target.DOShakeAnchorPos(
    duration,                     // 0.4초
    new Vector2(strength, 0f),    // 좌우로만 15픽셀 (Y값 0)
    vibrato,                      // 10번
    randomness,                   // 90도 안에서 방향을 섞음
    false,                        // snapping: 픽셀 단위로 끊지 않음
    true                          // fadeOut: 갈수록 약해짐
);
```

| 인자 | 바꾸면 |
|---|---|
| 세기 `Vector2(x, y)` | `(0, 15)` 면 위아래로만, `(15, 15)` 면 사방으로 |
| `vibrato` | 클수록 잘게 많이 떤다 |
| `randomness` | 0 이면 정확히 좌우 왕복, 클수록 방향이 섞인다 |
| `fadeOut` | `false` 면 끝까지 같은 세기로 떨다 뚝 멈춘다 |

20번 게이지(`GaugeDamageDelay.cs` 64행), 33번 크로매틱(`ChromaticHitEffect.cs` 26행), 42번 글리치(`GlitchEffect.cs` 30행)도 이 함수를 씁니다. 글리치는 `snapping = true` 로 "딱딱 끊기게" 씁니다.

### 6. 무한 반복 — 0205

`PulseEffect.cs` 11–35행

```csharp
private void OnEnable()  { StartPulse(); }
private void OnDisable() { pulseTween?.Kill(); }

private void StartPulse()
{
    transform.localScale = Vector3.one;
    pulseTween = transform.DOScale(maxScale, duration)   // 1.15배, 0.6초
        .SetEase(Ease.InOutSine)
        .SetLoops(-1, LoopType.Yoyo); // -1: 무한 반복, Yoyo: 커졌다 작아졌다 반복
}
```

| 반복 방식 | 모양 |
|---|---|
| `LoopType.Restart` (기본) | 1 → 1.15, 다시 1 에서 툭 시작 |
| `LoopType.Yoyo` | 1 → 1.15 → 1 → 1.15 (왕복) |
| `LoopType.Incremental` | 1 → 1.15 → 1.30 … 계속 커짐 |

- 무한 트윈은 **반드시 끌 곳**이 있어야 합니다. 여기서는 `OnDisable` 에서 `Kill`. 안 끄면 오브젝트가 꺼져도 트윈이 남습니다.
- `InOutSine` 은 양 끝에서 느려지는 곡선이라 숨 쉬는 느낌이 납니다.

## 정리

- 마우스 반응은 **포인터 이벤트 인터페이스**(`IPointerDown/Up/Enter/ExitHandler`)로 받는다. EventSystem + Raycast Target 이 있어야 온다.
- 크기 연출은 `Awake()` 에서 `originalScale` 을 기억하고, 누름·뗌·**벗어남** 모두 그 값으로 돌아오게.
- 리플은 클릭 화면 좌표를 `ScreenPointToLocalPointInRectangle` 로 부모 안 좌표로 바꾸고, Mask 로 자른다.
- `DOShakeAnchorPos` 는 세기 `Vector2` 로 방향을 정한다. 좌우만 = `(세기, 0)`.
- 무한 반복 `SetLoops(-1, LoopType.Yoyo)` 는 `OnDisable` 에서 꼭 `Kill`.

## 과제

**과제 1. 손맛 버튼 하나** — 새 씬(또는 `12_ButtonRipple` 복사본)에 버튼 하나를 만들고 아래를 **모두** 붙인다.
- 눌림(`ButtonPressEffect`) + 리플(`ButtonRipple`) + 호버(`ButtonHoverHighlight`, Target Image 연결)
- 값 세 개 이상을 기본값과 다르게 바꾸고, 바꾼 까닭을 한 줄씩 쓴다.

**과제 2. 틀렸을 때 흔들기** — 실습 4의 `EmptyInputShake` 를 고쳐, 글자가 4자보다 짧아도 흔들리게 한다 (`input.text.Length`).

| 제출물 | 채점 기준 | 배점 |
|---|---|---|
| 동작 영상 (10초 안쪽) | 호버 → 누름 → 뗌 순서로 세 반응이 모두 보인다. 누른 채 밖으로 나가도 크기가 돌아온다 | 35 |
| 값 바꾼 표 | 3개 이상, 바꾼 까닭이 구체적이다 (예: "0.1초는 너무 빨라 안 보여서 0.15") | 20 |
| `EmptyInputShake.cs` | 컴파일 오류 없음. 빈 칸·짧은 글자에서 흔들리고, 4자 이상이면 안 흔들린다 | 35 |
| 공통 | 파일 이름 `이름_02_번호`, 커밋 메시지 `2차시 과제` | 10 |

## 확인 질문

1. `ButtonPressEffect` 에 `IPointerExitHandler` 가 없으면 어떤 일이 생길까?
   - **정답**: 누른 채 마우스를 버튼 밖으로 끌어내면 `OnPointerExit` 복귀가 없어서, 버튼이 0.9배로 줄어든 채 남을 수 있다. 그래서 벗어날 때도 원래 크기로 돌린다.
2. `11_ButtonHover` 에서 색이 바뀌지 않는 까닭은? 오류가 나지 않는 까닭은?
   - **정답**: 씬의 **Target Image** 칸이 비어 있어서다. 코드가 `if (targetImage != null)` 일 때만 `DOColor` 를 하므로 비어 있어도 오류 없이 크기만 바뀐다.
3. `PulseEffect` 가 `OnDisable` 에서 `pulseTween?.Kill()` 을 하는 까닭은?
   - **정답**: `SetLoops(-1, …)` 는 끝나지 않는 트윈이라, 오브젝트를 꺼도 스스로 멈추지 않는다. 꺼질 때 지워야 다시 켤 때(`OnEnable`) 새로 깨끗하게 시작한다.

## 자주 막히는 곳

| 증상 | 원인 | 해결 |
|---|---|---|
| 마우스를 올려도 아무 반응 없음 | Game 창에 초점이 없음 / Raycast Target 꺼짐 / 위를 다른 UI 가 덮음 | Game 창 클릭, Image 의 **Raycast Target** 확인 |
| 모든 UI 가 반응 없음 | 씬에 EventSystem 이 없음 | 다른 씬에서 `EventSystem` 복사. 입력 모듈은 `InputSystemUIInputModule` |
| Console `InvalidOperationException: You are trying to read Input using the UnityEngine.Input class` | 옛 입력 모듈(`StandaloneInputModule`)을 넣음 | EventSystem 의 입력 모듈을 `Input System UI Input Module` 로 바꾼다 |
| 리플이 엉뚱한 자리에서 퍼짐 | `rippleCircle` 의 부모가 바뀜 | `RippleCircle` 을 `RippleMask` 아래에 둔다 |
| 리플이 버튼 밖까지 보임 | `RippleMask` 의 Mask 를 끔 | Mask 다시 켜기 |
| `EmptyInputShake` 에서 `NullReferenceException` | **Input**·**Shake** 칸 비어 있음 | 실습 4-4 |
| On Click 함수 목록에 `Submit` 이 없음 | 오브젝트 칸이 `TestInputField` 가 아님 / 컴파일 오류 | Console 오류 먼저 고치기 |
| `TogglePulse` 후 아이콘이 1.15배로 멈춤 | `transform.DOKill()` 을 빼먹어 복귀 트윈과 새 펄스가 겹침 | 실습 5-1 코드 그대로 |
| 펄스가 계속 커지기만 함 | `LoopType.Incremental` 로 바꿈 | `LoopType.Yoyo` |
