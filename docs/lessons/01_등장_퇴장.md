## 개념 설명

### 1. 용어

| 용어 | 한 줄 풀이 |
|---|---|
| 트윈 (Tween) | 시작 값에서 목표 값까지 정한 시간 동안 조금씩 바꾸는 것. "사이(between)를 채운다" |
| Ease (이징) | 시간에 따라 빠르기가 바뀌는 모양. 처음 빠르고 끝 느림, 끝에서 넘침 등 |
| `DOKill()` | 그 대상에 걸린 트윈을 지금 멈추고 지움 |
| CanvasGroup | 자식 UI 전체의 알파·클릭을 한 번에 다루는 컴포넌트 |
| `anchoredPosition` | 앵커(부모 안의 기준점)에서 얼마나 떨어졌는지. UI 위치는 보통 이것으로 옮긴다 |
| Sequence (시퀀스) | 트윈 여러 개를 순서·동시에 묶은 한 줄기 |
| 콜백 (Callback) | "끝나면 이걸 해" 처럼 나중에 불릴 코드. `OnComplete(() => …)` |

### 2. 한 줄 읽는 법

`FadeInOut.cs` 12–13행 (찾을 글자: `DOFade(1f`)

```csharp
targetGroup.DOFade(1f, duration)
    .SetEase(Ease.OutQuad);
```

| 부분 | 칸 | 이 줄에서 |
|---|---|---|
| `targetGroup` | 대상 | 패널의 CanvasGroup |
| `DOFade(1f, …)` | 무엇을 · 목표 값 | 알파를 1 로 |
| `duration` | 시간 | 0.5초 (7행, 씬 값도 0.5) |
| `.SetEase(Ease.OutQuad)` | 느낌 | 처음 빠르고 끝에서 천천히 멈춤 |

DOTween 함수 이름은 거의 `DO + 바꿀 것` 입니다: `DOFade`(알파), `DOScale`(크기), `DOAnchorPos`(UI 위치), `DOColor`(색).

### 3. 이 차시의 Ease 짝

[그림: 가로 시간, 세로 값. OutQuad·InQuad·OutCubic·InCubic·OutBack·InBack 여섯 곡선. OutBack 은 1 위로 살짝 넘침]

| 용어 | 열 때 | 닫을 때 | 까닭 |
|---|---|---|---|
| 0101 페이드 | `OutQuad` | `InQuad` | 나타날 땐 빨리 보이고, 사라질 땐 천천히 시작 |
| 0102 스케일 | `OutBack` | `InBack` | 넘쳤다 돌아옴 = "통통" 튀는 느낌 (`ScalePopup.cs` 26행 주석: "통통 튀는 느낌의 핵심") |
| 0103 슬라이드 | `OutCubic` | `InCubic` | Quad 보다 더 강하게 감속 |
| 0104 토스트 | `OutQuad` (올라오기) | 기본값 (사라지기) | |
| 0105 팝업 | `OutBack` | `InBack` | 0102 와 같은 짝 (`docs/animation/21-popup-open-close.md`: "짝을 맞추면 자연스러움") |

규칙: **열기 = Out 계열, 닫기 = In 계열**. Out 은 "끝에서 느려짐", In 은 "처음에 느림".

### 4. CanvasGroup 세 칸

| 칸 | 0 / false 이면 | 쓰인 곳 |
|---|---|---|
| `alpha` | 안 보임 (자식 전체) | 모든 용어 |
| `blocksRaycasts` | 마우스 클릭이 **뚫고 지나감** | 07·08·09: 사라진 뒤 `false` |
| `interactable` | 버튼 등이 눌리지 않음 | 21: 닫히는 동안 `false` |

`FadeInOut.cs` 17–23행 (찾을 글자: `public void FadeOut`)

```csharp
public void FadeOut()
{
    targetGroup.DOKill();
    targetGroup.DOFade(0f, duration)
        .SetEase(Ease.InQuad)
        .OnComplete(() => targetGroup.blocksRaycasts = false); // 페이드 아웃 후 클릭 막기
}
```

- 알파 0 이어도 `blocksRaycasts` 가 켜져 있으면, **안 보이는 패널이 뒤 버튼 클릭을 가로챕니다**.
- 그래서 "다 사라진 **뒤**" (`OnComplete`) 에 끕니다. 시작할 때 끄면 사라지는 동안 클릭이 뚫립니다.

**슬라이드의 숨는 위치** — `SlideInOut.cs` `Awake()` (찾을 글자: `offScreenPos =`)

```csharp
onScreenPos = targetPanel.anchoredPosition;
offScreenPos = onScreenPos + new Vector2(targetPanel.rect.width, 0f);
targetPanel.anchoredPosition = offScreenPos;
```

플레이 시작 때 씬에 놓인 위치를 "보일 위치"로 기억하고, 패널 폭만큼 오른쪽을 "숨는 위치"로 정합니다.

### 5. `DOKill()` — 연타에 강한 코드

[그림: 시간 줄. FadeIn 트윈이 0.25초쯤 진행 중 FadeOut 이 눌림. DOKill 없으면 두 트윈이 겹쳐 싸움, 있으면 앞 트윈이 지워지고 지금 값에서 0 으로]

- 거의 모든 항목이 트윈 앞에 `DOKill()` 을 씁니다 (`docs/README.md` "자주 쓰는 DOTween 패턴").
- 시퀀스는 변수에 담아 두고 `currentSequence?.Kill();` 로 지웁니다 (`ToastPopup.cs` 30행, `PopupOpenClose.cs` 28·47행).
- `?.` 는 "비어 있지 않을 때만" 부른다는 C# 문법입니다. 처음 한 번은 비어 있으니까요.

### 6. 시퀀스 — 토스트와 팝업

`ToastPopup.cs` 35–39행 (찾을 글자: `currentSequence.Append`)

```csharp
currentSequence = DOTween.Sequence();
currentSequence.Append(toastPanel.DOAnchorPos(originalPos, showDuration).SetEase(Ease.OutQuad));
currentSequence.Join(toastGroup.DOFade(1f, showDuration));
currentSequence.AppendInterval(stayDuration);
currentSequence.Append(toastGroup.DOFade(0f, hideDuration));
```

| 함수 | 뜻 | 이 코드에서 |
|---|---|---|
| `Append` | 앞 것이 끝나면 이어서 | ① 위로 올라오기 (0.3초) |
| `Join` | 바로 앞 `Append` 와 **동시에** | ① 과 함께 나타나기 |
| `AppendInterval` | 그냥 기다리기 | ② 1.5초 머묾 |
| `Append` | 이어서 | ③ 사라지기 (0.3초) |

[그림: 시간 막대. 0~0.3 올라오기+나타나기(위아래 두 줄), 0.3~1.8 대기, 1.8~2.1 사라지기. 전체 2.1초]

팝업(`PopupOpenClose.cs` 36–39행, 50–54행)은 딤·크기·알파 세 트윈을 `Append` 하나 + `Join` 둘로 동시에 돌립니다.
닫기 끝에는 `currentSequence.OnComplete(() => popupRoot.SetActive(false));` 로 팝업 전체를 끕니다.

| 값 | 기본값 | 하는 일 |
|---|---|---|
| `openDuration` | 0.35 | 열리는 시간 |
| `closeDuration` | 0.2 | 닫히는 시간 (열기보다 짧게) |
| `startScale` | 0.7 | 0 이 아니라 0.7 에서 시작 → 덜 과장됨 |

> **주의 (21번)**: 문서에 "PopupController (PopupOpenClose) ← Popup 에 붙이면 Awake 에서 자기 자신을 꺼버림" 이 있습니다. `Awake()` 가 `popupRoot.SetActive(false)` 를 하므로, 스크립트를 `Popup` 에 붙이면 스크립트까지 같이 꺼집니다. 그래서 따로 `PopupController` 에 붙였습니다.

### 실습 4. 새 스크립트: 아래에서 올라오며 나타나기 `FadeSlideIn` (25분)

목표: 0101(페이드) + 0104(아래에서 올라오기)를 합친 등장을 직접 만든다.

1. Project 창 `Assets/01_Scripts/Animation` 우클릭 → **Create → Scripting → MonoBehaviour Script** → 이름 `FadeSlideIn`.
   - 버전 차이: Unity 6 이전은 **Create → C# Script**. 메뉴 위치가 다르면 **Create** 아래에서 `MonoBehaviour Script` 를 찾는다
2. 내용을 모두 지우고 아래를 넣는다.

   ```csharp
   using UnityEngine;
   using DG.Tweening;

   // 아래에서 distance 만큼 올라오면서 나타나고, 내려가면서 사라짐
   public class FadeSlideIn : MonoBehaviour
   {
       [SerializeField] private RectTransform panel;
       [SerializeField] private CanvasGroup group;
       [SerializeField] private float distance = 80f;
       [SerializeField] private float duration = 0.4f;

       private Vector2 homePos;
       private Sequence seq;

       private void Awake()
       {
           homePos = panel.anchoredPosition; // 씬에 놓인 자리 = 보일 자리
       }

       public void Show()
       {
           seq?.Kill();
           panel.anchoredPosition = homePos - new Vector2(0f, distance);
           group.alpha = 0f;
           group.blocksRaycasts = true;

           seq = DOTween.Sequence();
           seq.Append(panel.DOAnchorPos(homePos, duration).SetEase(Ease.OutCubic));
           seq.Join(group.DOFade(1f, duration * 0.8f));
       }

       public void Hide()
       {
           seq?.Kill();
           seq = DOTween.Sequence();
           seq.Append(panel.DOAnchorPos(homePos - new Vector2(0f, distance), duration).SetEase(Ease.InCubic));
           seq.Join(group.DOFade(0f, duration * 0.8f));
           seq.OnComplete(() => group.blocksRaycasts = false);
       }

       private void OnDestroy()
       {
           seq?.Kill();
       }
   }
   ```

3. 저장 → Unity 로 돌아가 컴파일을 기다린다.
   - 확인: Console 에 빨간 오류 없음
4. `07_FadeInOut` 에서 `FadePanel` 선택 → **Add Component** → `Fade Slide In`. **Panel** 칸에 `FadePanel` 자신, **Group** 칸에 `FadePanel` 의 CanvasGroup 을 끌어 넣는다.

## 정리

- 트윈 한 줄 = **대상 · 목표 값 · 시간 · Ease**. 이름은 `DO + 바꿀 것`.
- 열기 = `Out` 계열, 닫기 = `In` 계열. 통통 튀는 팝업은 `OutBack` / `InBack` 짝.
- 트윈 앞에는 `DOKill()`, 시퀀스는 변수에 담아 `?.Kill()`. 연타해도 튀지 않는다.
- 안 보이게 한 뒤에는 `blocksRaycasts = false` 를 **`OnComplete` 에서**. 안 보이는 패널이 클릭을 가로채지 않게.
- 시퀀스: `Append`(이어서) · `Join`(동시에) · `AppendInterval`(기다리기) · `OnComplete`(끝나면).

## 과제

**과제 1. 내 패널 등장·퇴장 3종** — 빈 씬(또는 `07_FadeInOut` 복사본)에 패널 하나와 버튼 6개를 두고, 아래 세 가지를 만든다.
- ① 크기 + 알파 (OutBack / InBack), ② 왼쪽에서 슬라이드 (OutCubic / InCubic), ③ 실습 4의 `FadeSlideIn` 을 위에서 내려오게 고친 것
- 각각 "대상 · 목표 값 · 시간 · Ease" 를 표로 적는다.

**과제 2. 짧은 영상** — 세 가지를 차례로 열고 닫는 화면을 10초 안쪽으로 녹화한다.

| 제출물 | 채점 기준 | 배점 |
|---|---|---|
| 스크립트 (`.cs`) | 컴파일 오류 없음. 트윈 앞에 `DOKill` 또는 `?.Kill()` 이 있다 | 25 |
| 동작 영상 | 3종이 모두 열리고 닫힌다. 빠르게 연타해도 튀지 않는다 | 30 |
| 표 3줄 | 대상·목표 값·시간·Ease 를 모두 적었다 | 20 |
| 클릭 처리 | 닫힌 뒤 `blocksRaycasts = false` 를 `OnComplete` 에서 했다 | 15 |
| 공통 | 파일 이름 `이름_01_번호`, 커밋 메시지 `1차시 과제` | 10 |

## 확인 질문

1. 페이드 아웃이 끝났는데 그 자리 뒤의 버튼이 눌리지 않는다. 무엇을 빠뜨렸을까?
   - **정답**: CanvasGroup 의 `blocksRaycasts` 를 `false` 로 바꾸지 않았다. 알파 0 이어도 클릭을 받는다. `FadeInOut.cs` 처럼 `OnComplete` 에서 꺼야 한다.
2. `Append` 와 `Join` 은 어떻게 다른가? 토스트에서 예를 들어 보라.
   - **정답**: `Append` 는 앞 것이 끝난 뒤 이어서, `Join` 은 바로 앞 `Append` 와 동시에 돈다. 토스트는 올라오기(`Append`)와 나타나기(`Join`)를 동시에 하고, 기다린 뒤(`AppendInterval`) 사라지기(`Append`)를 이어 붙였다.
3. 팝업을 열 때 `OutBack`, 닫을 때 `InBack` 을 쓰는 까닭은?
   - **정답**: Out 은 끝에서 느려지며 살짝 넘쳤다 돌아와 "톡 튀어나오는" 느낌, In 은 처음에 살짝 부풀었다 빨려 들어가는 느낌이다. 열기·닫기를 짝으로 맞추면 자연스럽다.
