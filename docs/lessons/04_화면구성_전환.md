## 개념 설명

### 1. 용어

| 용어 | 한 줄 풀이 |
|---|---|
| Layout Group | 자식 UI 를 세로·가로로 자동 배치하는 컴포넌트. `VerticalLayoutGroup` 은 위에서 아래로 쌓는다 |
| LayoutElement | "나는 이만큼 높이를 원한다" 를 Layout Group 에 알려 주는 컴포넌트 |
| ContentSizeFitter | 자식들 크기에 맞춰 자기 크기를 늘이고 줄이는 컴포넌트 |
| RectMask2D | 사각형 밖으로 나간 자식을 잘라 보이지 않게 하는 컴포넌트 (Mask 보다 가볍고 사각형만) |
| 드래그 (Drag) | 누른 채 끄는 것. 시작·도중·끝 세 이벤트로 받는다 |
| 스냅 (Snap) | 놓았을 때 가장 가까운 자리로 착 붙는 것 |
| 플릭 (Flick) | 짧고 빠르게 튕기는 손짓 |
| `scaleFactor` | 캔버스가 화면에 맞추려고 키운 배율. 화면 픽셀 ÷ 배율 = 캔버스 단위 |
| Anchor (앵커) | UI 가 부모의 어느 점·변에 붙어 있는지. 부모가 커지면 붙은 변이 따라 움직인다 |

### 2. 아코디언 — 높이 하나만 트윈 (0401)

[그림: AccordionList(VerticalLayoutGroup + ContentSizeFitter) 아래 Item1~4. Item 안 Header(높이 90) + Content(높이 0→150). Content 가 커지면 Item2~4 가 아래로 밀림]

`AccordionItem.cs` 54–73행 (찾을 글자: `private void Animate`)

```csharp
// LayoutElement.preferredHeight 를 트윈하면 부모의 VerticalLayoutGroup 이 매 프레임 다시 배치해서
// 아래 항목들이 자연스럽게 밀려나고 당겨짐
heightTween?.Kill();
heightTween = DOTween.To(
        () => contentLayout.preferredHeight,
        h => contentLayout.preferredHeight = h,
        expand ? expandedHeight : 0f,
        duration)
    .SetEase(expand ? Ease.OutCubic : Ease.InOutCubic);

contentGroup.DOFade(expand ? 1f : 0f, expand ? duration : duration * 0.6f);
icon.DOLocalRotate(new Vector3(0f, 0f, expand ? 45f : 0f), duration).SetEase(Ease.OutBack);
```

- 아래 항목의 **위치를 계산하지 않습니다**. 높이만 바꾸면 Layout Group 이 다시 쌓습니다.
- `preferredHeight` 는 트윈 함수가 없어서 3차시의 `DOTween.To` 를 씁니다.
- `closeOthers` 가 켜져 있으면 `Expand()` 가 같은 부모의 다른 `AccordionItem` 을 모두 `Collapse()` 합니다 (36–43행).

| 필드 | 기본값 | 하는 일 |
|---|---|---|
| `expandedHeight` | 200 (데모 150) | 펼친 본문 높이 |
| `duration` | 0.3 | 펼침·접힘 시간 |
| `closeOthers` | true | 하나만 열리게 |
| `startExpanded` | false | 시작할 때 펼침 |

> **ContentSizeFitter 가 꼭 필요** (`docs/animation/22-accordion-expand.md`, `docs/scene-builder.md`): `AccordionList` 에 없으면 리스트 높이가 0 이라서 Layout Group 이 항목들을 최소 높이(0)로 찌그러뜨립니다. Layout Group 이 정한 RectTransform 값은 씬 파일에 저장되지 않고(0 으로 저장), 열 때 다시 계산되기 때문입니다.

### 3. 페이지 스와이프 — 드래그와 판정 (0402)

`PageSwipe.cs` 41–64행

```csharp
public void OnDrag(PointerEventData eventData)
{
    // 화면 픽셀 이동량을 캔버스 단위로 변환
    dragOffset += eventData.delta.x / canvas.scaleFactor;

    float x = dragStartX + dragOffset;
    float minX = -(pageCount - 1) * pageWidth;
    if (x > 0f) x *= edgeResistance;                               // 첫 페이지 왼쪽 바깥
    else if (x < minX) x = minX + (x - minX) * edgeResistance;     // 마지막 페이지 오른쪽 바깥

    content.anchoredPosition = new Vector2(x, content.anchoredPosition.y);
}

public void OnEndDrag(PointerEventData eventData)
{
    float elapsed = Mathf.Max(0.01f, Time.unscaledTime - dragStartTime);
    float velocity = dragOffset / elapsed;

    int target = currentPage;
    if (dragOffset < -pageWidth * swipeThreshold || velocity < -flickSpeed) target++;
    else if (dragOffset > pageWidth * swipeThreshold || velocity > flickSpeed) target--;

    GoToPage(target);
}
```

| 단계 | 하는 일 |
|---|---|
| 끄는 중 | 트윈 없이 `anchoredPosition` 을 **직접** 옮긴다. 손가락을 바로 따라와야 하니까 |
| 양 끝 바깥 | 넘친 만큼에 `edgeResistance`(0.35)를 곱해 덜 움직인다 |
| 놓을 때 | **거리**(페이지 폭의 20%) **또는** **속도**(1500/초) 중 하나만 넘어도 넘김 |
| 스냅 | `content.DOAnchorPosX(-currentPage * pageWidth, snapDuration).SetEase(Ease.OutCubic)` (71행) |

`eventData.delta` 는 **화면 픽셀**입니다. 캔버스는 1920×1080 기준으로 늘었다 줄었다 하므로(`CanvasScaler`, `docs/scene-builder.md`) `scaleFactor` 로 나눠 캔버스 단위로 맞춥니다.

### 4. 탭 밑줄 — 젤리 (0403)

`TabIndicator.cs` 59–66행 (찾을 글자: `'젤리' 느낌`)

```csharp
float distance = Mathf.Abs(targetPos.x - indicator.anchoredPosition.x);
float stretchedWidth = Mathf.Max(targetWidth, Mathf.Min(targetWidth * stretchRatio, targetWidth + distance));

DOTween.Sequence()
    .SetTarget(indicator)
    .Append(indicator.DOAnchorPos(targetPos, duration).SetEase(Ease.OutCubic))                                   // 0~0.35 이동
    .Join(indicator.DOSizeDelta(new Vector2(stretchedWidth, height), duration * 0.4f).SetEase(Ease.OutQuad))     // 0~0.14 늘어남
    .Insert(duration * 0.4f, indicator.DOSizeDelta(new Vector2(targetWidth, height), duration * 0.6f).SetEase(Ease.OutBack)); // 0.14~0.35 돌아옴
```

[그림: 시간 막대. 위치 0~0.35 한 줄. 폭은 0~0.14 늘어남, 0.14~0.35 원래 폭(OutBack)]

- `.SetTarget(indicator)` 를 붙여 두면 `indicator.DOKill()` 한 번으로 이 시퀀스까지 지울 수 있습니다 (50행).
- 밑줄은 탭들과 **같은 부모** 아래에 있어서, 탭의 `anchoredPosition.x` 를 그대로 목표로 씁니다.
- 내용 페이지는 `direction = prevIndex < index ? 1f : -1f` (85행)로 들어오는 쪽을 정합니다.

| 필드 | 기본값 | 하는 일 |
|---|---|---|
| `duration` | 0.35 | 이동 시간 |
| `widthRatio` | 0.6 | 탭 폭 대비 밑줄 폭 |
| `stretchRatio` | 1.8 | 이동 중 늘어나는 최대 배율 |
| `pageSlideDistance` | 60 | 내용이 들어오는 거리 |

### 5. 카드 플립 — 반씩 나눠 돌리기 (0404)

`CardFlip.cs` 22–46행

```csharp
if (isFlipping) return;   // 연타 막기
isFlipping = true;
float half = duration * 0.5f;
Sequence seq = DOTween.Sequence();

// 1. 90도까지 돌려서 카드가 옆면(안 보이는 상태)이 되게 함
seq.Append(card.DOLocalRotate(new Vector3(0f, 90f, 0f), half).SetEase(Ease.InQuad));
seq.Join(card.DOScale(liftScale, half).SetEase(Ease.OutQuad));

// 2. 안 보이는 순간에 앞/뒷면 교체 후 반대편(-90도)에서 이어서 회전
seq.AppendCallback(() =>
{
    isFront = !isFront;
    ApplyFace();
    card.localEulerAngles = new Vector3(0f, -90f, 0f);
});

// 3. 0도로 돌아오며 새 면이 보임
seq.Append(card.DOLocalRotate(Vector3.zero, half).SetEase(Ease.OutQuad));
seq.Join(card.DOScale(1f, half).SetEase(Ease.InQuad));
seq.OnComplete(() => isFlipping = false);
```

[그림: 위에서 본 카드. 0° → 90°(옆면, 안 보임, 여기서 면 교체) → -90° 로 점프 → 0°]

- **가장 안 보이는 순간(90°)에 바꾼다** — 35번 픽셀화 전환도 "가장 거친 순간 이미지 교체" 로 같은 원리를 씁니다 (`docs/shader/35-pixelate-transition.md`).
- 카드 루트는 투명 이미지 + Button 으로 클릭만 받고, 앞·뒷면은 자식입니다 (`Build27_CardFlip.cs` 28–31행).

### 6. 스포트라이트 — 셰이더 없이 구멍 (0405)

`TutorialSpotlight.cs` 62–75행 (찾을 글자: `DOSizeDelta(size, moveDuration)`)

```csharp
Vector2 size = target.rect.size + Vector2.one * padding * 2f;   // 여백 40

DOTween.Sequence()
    .SetTarget(spotlight)
    .Append(spotlight.DOMove(target.position, moveDuration).SetEase(Ease.InOutCubic))
    .Join(spotlight.DOSizeDelta(size, moveDuration).SetEase(Ease.InOutCubic))
    .OnComplete(() =>
    {
        // 도착 후 숨 쉬듯 살짝 커졌다 작아졌다 하며 시선을 유도
        breatheTween = spotlight.DOSizeDelta(size * 1.06f, 0.8f)
            .SetEase(Ease.InOutSine)
            .SetLoops(-1, LoopType.Yoyo);
    });
```

- 위치는 `DOMove`(월드 위치)로 옮깁니다. 대상 UI 들의 부모가 달라도 같은 화면 자리로 갈 수 있습니다.
- 시작할 땐 `startSize` 2600 짜리 구멍에서 첫 대상으로 **줄어들며** 시선을 모읍니다 (40행).
- 끝나면 `overlayGroup.blocksRaycasts = false` (88행) — 1차시와 같은 규칙. 아래 UI 가 다시 눌립니다.
- 대상과 문구는 `Build28_TutorialSpotlight.cs` 71–76행 `SetArray(… "targets" …)`, `SetStrings(… "messages" …)` 에서 넣습니다.

## 정리

- 아코디언: **높이 하나만** 트윈(`LayoutElement.preferredHeight`) → Layout Group 이 나머지를 밀어 준다. 리스트에 ContentSizeFitter 필수, 본문은 RectMask2D 로 자른다.
- 스와이프: 끄는 중엔 직접 이동, 놓으면 **거리 또는 속도**로 판정 후 `DOAnchorPosX` 스냅. 화면 픽셀 ÷ `scaleFactor`.
- 탭 밑줄: 위치는 한 번에, 폭은 늘었다(`Join`) 돌아오기(`Insert`) → 젤리.
- 카드 플립: 90° 에서 면 교체 + -90° 로 점프. 연타는 `isFlipping` 으로 막는다.
- 스포트라이트: 구멍 이미지 + Anchor 로 붙은 어두운 사각형 4개. 구멍만 `DOMove` + `DOSizeDelta`.
- 오래 남길 기능은 빌더 코드(`BuildNN_*.cs`)에 넣고 **Build Scene** 으로 다시 만든다.

## 과제

**과제 1. 튜토리얼 바꾸기** — `28_TutorialSpotlight` 의 빌더 코드를 고쳐 강조 대상 하나를 **새로 만든 UI**(예: 오른쪽 아래 `SettingsButton`)로 바꾸고 문구를 고친다. `CreateButton(…)` 한 줄을 더해 만든다.

## 확인 질문

1. 아코디언에서 아래 항목들의 위치를 하나도 트윈하지 않는데 어떻게 밀려 내려가는가?
   - **정답**: 본문의 `LayoutElement.preferredHeight` 를 `DOTween.To` 로 트윈하면, 부모 `VerticalLayoutGroup` 이 매 프레임 자식들을 다시 쌓기 때문이다.
2. 페이지를 조금만 끌었는데도 다음 페이지로 넘어갔다. 왜일까?
   - **정답**: 넘김 판정이 "거리(페이지 폭의 `swipeThreshold` 20%) **또는** 속도(`flickSpeed` 1500)" 라서, 짧아도 빠르게 튕기면(플릭) 넘어간다.
3. 카드 플립에서 0° → 180° 를 한 번에 돌리지 않는 까닭은?
   - **정답**: UI 에는 뒷면이 따로 없어서 180° 를 돌리면 같은 면이 좌우로 뒤집혀 보인다. 90°(옆면, 안 보임)에서 앞·뒷면을 바꾸고 -90° 에서 0° 로 돌려야 새 면이 바른 방향으로 보인다.

## 자주 막히는 곳

| 증상 | 원인 | 해결 |
|---|---|---|
| 아코디언 항목이 찌그러져 겹침 | `AccordionList` 의 ContentSizeFitter 가 꺼짐 / 지움 | 다시 켜기 (Vertical Fit = Preferred Size) |
| 펼칠 때 글자가 칸 밖으로 삐져나옴 | `Content` 의 RectMask2D 가 꺼짐 | 다시 켜기 |
| 페이지가 손가락보다 빠르거나 느리게 따라옴 | `scaleFactor` 로 안 나눔 (내 코드) | `eventData.delta.x / canvas.scaleFactor` |
| 드래그가 안 됨 | `Viewport` Image 의 Raycast Target 꺼짐 | 다시 켜기 (거의 투명한 Image 가 드래그를 받는다) |
| 탭 밑줄이 엉뚱한 x 로 감 | 밑줄을 탭과 다른 부모로 옮김 | `Indicator` 를 `TabBar` 아래에 둔다 |
| 카드 글자가 좌우로 뒤집혀 보임 | 내 코드에서 180° 를 한 번에 돌림 | 90° 에서 면 교체 + -90° 로 점프 |
| **Flip All** 버튼이 안 생김 | **Build Scene** 을 안 돌림 / 컴파일 오류 | Console 확인 후 메뉴 다시 |
| Console `IndexOutOfRangeException` (Build27) | `flips[i] = flip;` 를 `for` 밖에 넣음 | 실습 4-4 위치 확인 |
| 튜토리얼 문구가 비어 있음 | `targets` 보다 `messages` 가 적음 | 개수를 맞춘다 (코드는 모자라면 빈 글자) |
| 튜토리얼이 끝났는데 아래 버튼이 안 눌림 | 내 코드에서 `blocksRaycasts = false` 를 뺌 | `EndTutorial()` 확인 |
