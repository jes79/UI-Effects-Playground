## 학습 목표

1. 왜곡 셰이더의 기본 — "색을 바꾸지 않고 **읽을 uv 를 살짝 민다**" — 를 6개 예제에서 찾고, 미는 양이 `sin`·노이즈·랜덤 중 무엇에서 오는지 구분할 수 있다.
2. RGB 를 세 번 나눠 읽는 색 분리, 시간 양자화(`floor(_Time.y * 속도)`), 높이 마스크 같은 노이즈 기법을 쉬운 말로 설명할 수 있다.
3. URP 에서 UI 셰이더가 화면 뒤를 못 읽는(GrabPass 없음) 문제를 41번이 어떻게 풀었는지 말하고, 효과 스크립트를 고쳐 새 기능(랜덤 리플)을 더할 수 있다.

## 개념 설명

### 1. 용어

| 용어 | 한 줄 풀이 |
|---|---|
| 왜곡 (Distortion) | 그림을 휘어 보이게 하는 것. 픽셀이 읽는 자리(uv)를 옆으로 민다 |
| 오프셋 (Offset) | 미는 양. `SampleUI(uv + offset)` |
| 색 분리 / 크로매틱 애버레이션 | 빨강·초록·파랑을 서로 다른 자리에서 읽어 색이 갈라져 보이게 하는 것. 렌즈 수차 흉내 |
| 스캔라인 (Scanline) | 옛 모니터처럼 가로로 가는 줄무늬 |
| 양자화 (Quantize) | 이어진 값을 계단처럼 끊는 것. `floor(시간 × 16)` = 1/16초마다 한 계단 |
| GrabPass | 화면에 이미 그려진 것을 텍스처로 가져오는 기능. URP 의 UI 셰이더에서는 못 쓴다 |
| 블러 (Blur) | 주변 픽셀을 평균 내어 흐리게 |
| Fbm | 노이즈를 4겹 겹친 것. 크고 작은 무늬가 섞여 자연스럽다 |

### 2. 왜곡의 기본 — uv 밀기

`docs/shader/40-wave-distortion.md`: "왜곡 셰이더의 기본: 색을 바꾸지 않고 **샘플링할 uv 를 살짝 밀어서** 그림이 휘어 보이게 함"

[그림: 왼쪽 원래 격자, 오른쪽 각 픽셀이 uv + offset 을 읽어 격자가 휘어 보임. 화살표 = offset]

| 용어 | 미는 양을 만드는 것 | 시간 |
|---|---|---|
| 0801 | 방향 × (`_Amount` + 노이즈 떨림) — 채널마다 반대로 | `ValueNoise(_Time.y * 8)` 떨림 |
| 0803 | `sin(uv.y …)`, `cos(uv.x …)` + 클릭 링 | `_Time.y * _Speed` |
| 0804 | 노이즈 + 가장자리 렌즈 (배경 uv 를 밈) | 아주 천천히 |
| 0805 | 줄마다·블록마다 `Hash21` 랜덤 | `floor(_Time.y * 16)` 계단 |
| 0806 | `Fbm` 노이즈 두 개 × 높이 마스크 | 노이즈 y 에서 시간 빼기 → 위로 |
| 0802 | (밀지 않음) 색을 단색으로 바꾸고 줄·띠·깜빡임을 곱함 | 스캔라인·띠·깜빡임 |

밀어서 0~1 밖을 읽으면 텍스처 가장자리가 늘어나 보입니다. 그래서 `InsideUV(uv)` 를 곱해 밖은 0 으로 만듭니다 (33·42번).

### 3. 색 분리 — 0801

`ChromaticAberration.shader` 75–86행

```c
// 시간에 따라 조금씩 흔들리는 오프셋 (크기와 방향 모두)
float n = ValueNoise(float2(_Time.y * _JitterSpeed, 0.0)) - 0.5;
float2 dir = AngleToDir(_Angle + n * 90.0);
float2 off = dir * (_Amount + n * 2.0 * _JitterAmount);

fixed4 r = SampleUI(uv + off) * InsideUV(uv + off);    // 빨강은 +쪽에서
fixed4 g = SampleUI(uv);                                // 초록은 제자리
fixed4 b = SampleUI(uv - off) * InsideUV(uv - off);    // 파랑은 -쪽에서

fixed4 c;
c.a = max(max(r.a, g.a), b.a);                          // 세 알파 중 최대 → 갈라진 색이 밖으로 삐져나옴
c.rgb = float3(r.r * r.a, g.g * g.a, b.b * b.a) / max(c.a, 1e-4);
```

`ChromaticHitEffect.cs` 18–27행 — **피격 기본 패턴: 최대치로 즉시 → 원래 값으로 트윈**

```csharp
material.DOKill();
material.SetFloat(Amount, hitAmount);                                     // 0.05 로 바로
material.DOFloat(idleAmount, Amount, hitDuration).SetEase(Ease.OutQuad);  // 0.004 로 0.5초
TargetRect.DOShakeAnchorPos(0.3f, shakeStrength, 25, 90f, false, true);   // 20 세기
```

| 값 | 기본값 |
|---|---|
| `_Amount` (평소 `idleAmount`) / 피격 `hitAmount` | 0.004 / 0.05 |
| `_Angle` | 0 |
| `_JitterSpeed` / `_JitterAmount` | 8 / 0.003 |
| `hitDuration` / `shakeStrength` | 0.5 / 20 |

### 4. 홀로그램 — 단색 + 줄 + 깜빡임 + 스캔 켜기 (0802) · 선택

`HologramScanline.shader` 84–108행 요점

```c
float3 col = _HoloColor.rgb * (0.35 + Gray(src.rgb) * 1.2);                               // 원래 밝기만 남기고 하늘색
float lines = sin((uv.y * _LineCount - _Time.y * _LineSpeed) * 6.2831853) * 0.5 + 0.5;    // 120줄이 흘러내림
float band = exp(-pow((uv.y - frac(_Time.y * _BandSpeed)) * 10.0, 2.0));                  // 밝은 띠가 아래→위
float flicker = 0.85 + 0.15 * ValueNoise(float2(_Time.y * _FlickerSpeed, 3.7));           // 불안정한 깜빡임

float revealLine = _Reveal * 1.1;
float reveal = 1.0 - smoothstep(revealLine - 0.04, revealLine, uv.y);                      // 선 아래만 보임
float revealEdge = exp(-pow((uv.y - revealLine) * 50.0, 2.0)) * saturate(_Reveal * 20.0); // 선 위치에 밝은 줄
```

- 홀로그램 = **단색 치환 + 스캔라인 + 깜빡임 + 반투명** 조합 (`docs/shader/36-hologram-scanline.md`).
- 계속 도는 줄·띠·깜빡임은 `_Time` (셰이더), 켜고 끄기 `_Reveal` 만 DOTween (`HologramEffect.cs`: 켜기 1.0초 `OutCubic` + 끝나면 `DOShakeAnchorPos`, 끄기 0.4초 `InQuad`).
- 7차시 그라디언트 마스크처럼 **`_Reveal` 선 아래만 보이게** 해서 "스캔되며 켜지는" 등장이 됩니다.

### 5. 물결 + 클릭 리플 — 0803

`WaveDistortion.shader` 85–99행

```c
// 기본 일렁임: x 는 y 에 따라, y 는 x 에 따라 흔들림
offset.x = sin(uv.y * _Frequency + t) * _Amplitude;
offset.y = cos(uv.x * _Frequency * 0.8 + t * 1.3) * _Amplitude * 0.6;

// 클릭 리플: 반지름이 progress 에 따라 커지는 링 모양 파동
float2 rp = (uv - _RippleCenter.xy) * float2(_Aspect, 1.0);
float d = length(rp);
float radius = _RippleProgress * 1.2;
float fade = 1.0 - _RippleProgress;
float wave = sin((d - radius) * 60.0) * exp(-pow((d - radius) / _RippleWidth, 2.0)) * fade;
float2 dir = rp / max(d, 1e-4);
offset += dir / float2(_Aspect, 1.0) * wave * _RippleStrength;

fixed4 c = SampleUI(uv + offset) * i.color;
```

- 리플은 클릭 점에서 거리 `d` 가 **반지름 근처일 때만**(`exp(-x²)` 종 모양) 바깥 방향 `dir` 으로 밉니다 → 링 모양 파동.
- `_RippleProgress` 1 = 리플 없음. 클릭하면 0 → 1 로 트윈합니다.

`WaveRippleEffect.cs` 26–39행 — 클릭 좌표 → uv

```csharp
if (!RectTransformUtility.ScreenPointToLocalPointInRectangle(TargetRect, eventData.position, eventData.pressEventCamera, out Vector2 local))
    return;

// 클릭 위치를 이미지 uv(0~1)로 변환해서 리플 중심으로
Vector2 uv = Rect.PointToNormalized(TargetRect.rect, local);
material.SetVector(RippleCenter, uv);

// 리플과 일렁임은 같은 머티리얼의 다른 프로퍼티라 material.DOKill() 대신 트윈을 각각 관리
rippleTween?.Kill();
material.SetFloat(RippleProgress, 0f);
rippleTween = material.DOFloat(1f, RippleProgress, rippleDuration).SetEase(Ease.OutSine);
```

- 2차시 12번 리플과 같은 좌표 변환 + `Rect.PointToNormalized` 로 0~1 uv.
- 7차시 액체처럼 **트윈 변수를 따로** (`rippleTween`, `waveTween`).
- 이미지 **Raycast Target** 이 켜져 있어야 클릭을 받습니다 (`Build40_WaveDistortion.cs` 17행).

### 6. 유리 — 뒤를 못 읽으니 배경을 넘긴다 (0804) · 선택

[그림: Canvas 안 GlassBackground(전체 화면) 와 GlassPanel. 셰이더에는 같은 배경 텍스처(_BackgroundTex) + 배경의 캔버스 Rect(_BgRect). 패널 픽셀의 worldPosition → 배경 uv]

`GlassRefraction.shader` 100–122행 요점

```c
// 이 픽셀 뒤에 있는 배경의 uv (캔버스 좌표 → 배경 Rect 기준 0~1)
float2 bgUV = (i.worldPosition.xy - _BgRect.xy) / _BgRect.zw;

// 굴절 1: 천천히 움직이는 노이즈로 울퉁불퉁한 유리 표면
float2 refractOffset = (float2(n1, n2) - 0.5) * _Distortion;
// 굴절 2: 가장자리로 갈수록 렌즈처럼 안쪽으로 휨
refractOffset -= normalize(p + 1e-5) * edgeFactor * edgeFactor * _EdgeBulge;

// 9탭 블러 (반투명 유리 느낌)
for (int x = -1; x <= 1; x++)
    for (int y = -1; y <= 1; y++)
        col += tex2D(_BackgroundTex, rUV + float2(x, y) * _BlurSize).rgb;
col /= 9.0;
```

- "URP 에서는 UI 셰이더가 **GrabPass(화면 뒤 내용 가져오기)를 쓸 수 없어요**" (`docs/shader/41-glass-refraction.md`). 그래서 머티리얼 `_BackgroundTex` 에 **배경과 같은 텍스처**를 넣고(`Build41_GlassRefraction.cs` 22행), 패널 자리에 해당하는 배경 부분을 다시 그립니다.
- `GlassPanel.cs` `LateUpdate()`(25–33행)가 매 프레임 배경의 네 모서리를 캔버스 좌표로 바꿔 `_BgRect` 로 넣습니다. 패널을 끌어도 뒤 배경이 맞습니다.
- 패널 모양은 스프라이트가 아니라 **둥근 사각형 SDF**(93–98행). 테두리 빛도 같은 거리 값으로 그립니다.
- 한계: 배경이 이 텍스처 **하나**일 때만 맞습니다. 패널 뒤에 다른 UI 가 있어도 비치지 않습니다.

|---|---|---|
| `_GlassTint` | (0.9, 0.95, 1, 0.15) | 유리 색, a = 세기 |
| `_Distortion` / `_NoiseScale` | 0.012 / 4 | 표면 울퉁불퉁 |
| `_EdgeBulge` | 0.03 | 가장자리 렌즈 굴절 |
| `_BlurSize` | 0.004 | 블러 |
| `_HighlightStrength` / `_BorderGlow` | 0.25 / 0.6 | 하이라이트 / 테두리 빛 |
| `_CornerRadius` | 0.12 | 모서리 둥글기 |

### 7. 글리치 — 계단 시간 + 랜덤 (0805)

`Glitch.shader` 73–79행

```c
float t = floor(_Time.y * _Speed); // 연속이 아니라 "툭툭" 끊기게 시간 양자화

// 가로 줄 단위로 랜덤하게 밀림
float row = floor(uv.y * _BlockCount);                              // 24줄 중 몇 번째
float rowRand = Hash21(float2(row, t));                             // 줄·시각마다 다른 랜덤
float rowActive = step(1.0 - _Intensity * 0.6, rowRand);           // 세기만큼만 고름
float shift = (Hash21(float2(t, row + 13.1)) - 0.5) * 0.25 * _Intensity * rowActive;
```

- `floor(_Time.y * 16)` → 1/16초 동안 같은 값 → 부드럽지 않고 **툭툭** 바뀝니다.
- 줄 밀림 + 큰 블록 밀림 + 33번식 RGB 분리 + 색 반전 + 스캔라인 노이즈를 `_Intensity` **하나**로 함께 키웁니다.

`GlitchEffect.cs` 22–47행

```csharp
public void Burst()
{
    material.DOKill();
    material.SetFloat(Intensity, burstIntensity);                                  // 1 로 바로
    material.DOFloat(idleIntensity, Intensity, burstDuration).SetEase(Ease.InExpo); // 0.05 로 0.35초
    TargetRect.DOKill(true);
    TargetRect.DOShakeAnchorPos(burstDuration * 0.6f, new Vector2(18f, 0f), 40, 0f, true, true); // snapping = true
}

private void ScheduleAutoBurst()
{
    autoBurstTimer = DOVirtual.DelayedCall(Random.Range(autoBurstInterval.x, autoBurstInterval.y), () =>
    {
        Burst();
        ScheduleAutoBurst();       // 콜백 안에서 다시 예약 → 코루틴 없이 랜덤 간격 반복
    });
}
```

### 8. 히트 웨이브 — 노이즈가 위로 (0806)

`HeatWave.shader` 78–88행

```c
// y 방향으로 길쭉하고 위로 흘러가는 노이즈 두 개 → x/y 오프셋
float n1 = Fbm(float2(uv.x * _Scale, uv.y * _Scale * 1.6 - t));
float n2 = Fbm(float2(uv.x * _Scale + 5.2, uv.y * _Scale * 1.6 - t * 1.3 + 1.7));

float heightMask = pow(saturate(1.0 - uv.y), _RiseFalloff);      // 아래(uv.y 0)일수록 1
float2 offset = (float2(n1, n2) - 0.5) * _Strength * heightMask;

fixed4 c = SampleUI(uv + offset) * i.color;

// 열기 톤 (강도가 0 이면 원본 그대로)
float tint = heightMask * _HeatTint.a * saturate(_Strength * 40.0);
c.rgb = lerp(c.rgb, c.rgb * _HeatTint.rgb * 1.4, tint);
```

- 노이즈 y 좌표에서 시간을 **빼면**(`- t`) 무늬가 위로 올라갑니다.
- `pow(1 - uv.y, 1.2)` → 아래쪽(열원)일수록 세게.
- `saturate(_Strength * 40.0)` — **Toggle Heat** 로 세기가 0 이 되면 붉은 톤도 같이 사라집니다.
- 스크립트는 `_Strength` 0 ↔ 0.025 를 1초 `InOutSine` 으로 (`HeatWaveEffect.cs` 21–26행).

## 정리

- 왜곡 = 색을 바꾸지 않고 **읽을 uv 를 민다**. 미는 양이 `sin`(물결)·노이즈(아지랑이·유리)·랜덤(글리치)이냐가 다를 뿐.
- 밀어서 0~1 밖을 읽을 땐 `InsideUV` 로 0 처리.
- 색 분리 = R·G·B 를 다른 자리에서 세 번 읽고, 알파는 셋 중 최대.
- 홀로그램 = 단색 + 스캔라인 + 띠 + 깜빡임 + `_Reveal` 선 아래만 보이기.
- 글리치 = `floor(_Time.y * 속도)` 계단 시간 + 줄·블록별 `Hash21`. 자동 반복은 `DOVirtual.DelayedCall` 안에서 다시 예약.
- 유리 = GrabPass 대신 **같은 배경 텍스처 + 배경 Rect**. `worldPosition` 으로 "이 픽셀 뒤 배경 uv".
- 피격 패턴 = **최대치로 즉시 세팅 → 원래 값으로 트윈** (33 · 42 · 6차시 FlashTint).

## 확인 질문

1. 크로매틱 애버레이션에서 최종 알파를 세 채널 알파의 **최대값**으로 하는 까닭은?
   - **정답**: R 과 B 를 반대쪽으로 밀어 읽으므로, 원래 그림 밖에도 한 채널만 있는 픽셀이 생긴다. 최대값을 쓰면 그 갈라진 색이 그림 바깥으로 삐져나와 보인다.
2. 글리치가 부드럽게 변하지 않고 "툭툭" 끊겨 보이는 까닭을 코드로 말해 보라.
   - **정답**: `float t = floor(_Time.y * _Speed);` 로 시간을 계단처럼 끊었다. 1/16초 동안 `t` 가 같아서 `Hash21` 랜덤 값도 그동안 같고, 다음 계단에서 확 바뀐다.
3. 유리 패널이 화면 뒤를 직접 읽지 않고 `_BackgroundTex` 와 `_BgRect` 를 쓰는 까닭과, 그 한계는?
   - **정답**: URP 에서 UI 셰이더는 GrabPass 를 쓸 수 없어서 화면 뒤를 가져올 수 없다. 그래서 배경과 같은 텍스처와 그 캔버스 Rect 를 넘겨 패널 자리의 배경을 다시 그린다. 그 텍스처 하나만 비치므로, 패널 뒤의 다른 UI 는 굴절되어 보이지 않는다.
