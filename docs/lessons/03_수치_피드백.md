## 학습 목표

1. `DOPunchScale` 과 `DOScale` 의 차이(돌아오느냐, 머무느냐)를 말하고 알맞은 곳에 고를 수 있다.

## 개념 설명

### 1. 용어

| 용어 | 한 줄 풀이 |
|---|---|
| 펀치 (Punch) | 잠깐 튀었다가 **원래 값으로 돌아오는** 트윈. 끝나면 제자리 |
| `DOTween.To` | 정해진 함수가 없는 값도 트윈하는 만능 함수. "어디서 읽고(getter), 어디에 쓸지(setter)" 를 넘긴다 |
| getter / setter | 값을 읽는 함수 / 값을 쓰는 함수. `() => x` , `v => x = v` |
| 람다 (Lambda) | 이름 없이 그 자리에서 만드는 짧은 함수. `=>` 로 쓴다 |
| Slider | 0~1 사이 값을 막대로 보여 주는 UI. `value` 를 바꾸면 막대가 찬다 |
| Filled 이미지 | Image Type = Filled. `fillAmount`(0~1)만큼만 그린다 |
| `SetDelay` | 트윈을 정한 시간 뒤에 시작 |

### 2. 펀치 — 0301

`BadgeCountAnimation.cs` 20–29행 (찾을 글자: `DOPunchScale`)

```csharp
badgeText.text = newValue.ToString();

badgeTransform.DOKill();
badgeTransform.localScale = Vector3.one; // 혹시 이전 트윈이 덜 끝났을 때 대비해 초기화

// 살짝 커졌다가 원래 크기로 되돌아오는 펀치 효과
badgeTransform.DOPunchScale(Vector3.one * punchScale, duration, vibrato: 1, elasticity: 0.5f);
```

| 인자 | 값 | 뜻 |
|---|---|---|
| `punch` | `Vector3.one * 0.4` | 원래 크기에 **더할** 양. 1 → 최대 1.4 |
| `duration` | 0.3 | 전체 시간 |
| `vibrato` | 1 | 몇 번 떨지. 1 = 한 번 톡 |
| `elasticity` | 0.5 | 반대쪽으로 얼마나 되튈지 (0~1) |

| | `DOScale(1.4f, t)` | `DOPunchScale(0.4, t)` |
|---|---|---|
| 끝난 뒤 크기 | 1.4 에 머문다 | 1 로 돌아온다 |
| 어울리는 곳 | 팝업 열기 (1차시) | 숫자가 바뀐 순간, 획득 순간 |

**펀치 전에 `DOKill` + `localScale = Vector3.one`** 를 하는 까닭: 펀치는 "지금 크기 기준" 으로 튑니다. 펀치 도중(1.3배일 때) 또 누르면 1.3 기준으로 튀어서 점점 커집니다.

### 3. 겹쳐 넣기 `Insert` — 0302

`SuccessCheckEffect.cs` 37–45행 (찾을 글자: `seq.Insert(checkDelay`)

```csharp
Sequence seq = DOTween.Sequence();

// 1. 원이 통통 튀며 등장
seq.Append(circleTransform.DOScale(1f, circleDuration).SetEase(Ease.OutBack));
seq.Join(circleGroup.DOFade(1f, circleDuration * 0.6f));

// 2. 살짝 딜레이 후 체크마크가 튀어나오듯 등장
seq.Insert(checkDelay, checkMarkTransform.DOScale(1f, checkDuration).SetEase(Ease.OutBack));
seq.Insert(checkDelay, checkMarkGroup.DOFade(1f, checkDuration * 0.6f));
```

[그림: 시간 막대. 원 0~0.35, 체크 0.2~0.5. 0.2~0.35 구간이 겹침. 아래에 Append 로 했을 때(체크 0.35~0.65) 비교]

| 함수 | 체크가 시작하는 때 | 전체 시간 |
|---|---|---|
| `Insert(0.2f, …)` (지금) | 0.2초 — 원이 다 나오기 **전** | 0.5초 |
| `Append(…)` 로 바꾸면 | 0.35초 — 원이 다 나온 **뒤** | 0.65초 |

`Insert(시간, 트윈)` 은 "시퀀스 시작부터 몇 초에 끼워 넣기" 입니다. 앞뒤 순서와 상관없이 그 시각에 시작합니다. 24번 탭 인디케이터도 이것을 씁니다 (`docs/README.md` 패턴 표).

### 4. 아무 숫자 트윈 `DOTween.To` — 0303

`CountUpAnimation.cs` 20–28행

```csharp
countTween = DOTween.To(
    () => currentValue,           // getter: 현재 값을 어떻게 가져올지
    value => {                     // setter: 값이 갱신될 때마다 실행
        currentValue = value;
        countText.text = currentValue.ToString();
    },
    targetValue,                   // 목표 값
    duration
).SetEase(Ease.OutQuad);
```

- `DOFade`·`DOScale` 은 대상이 정해져 있습니다. 점수(`int`)는 그런 함수가 없으니 `DOTween.To` 에 **읽는 법·쓰는 법**을 알려 줍니다.
- setter 는 매 프레임 불립니다. 그 안에서 글자를 바꾸면 숫자가 굴러가 보입니다.
- `currentValue` 가 `int` 라서 `int` 판 `DOTween.To` 가 골라집니다. 정수로만 바뀝니다.
- 22번 아코디언(높이), 25번(외곽선 두께), 38번(수위)도 이것을 씁니다.

### 5. 막대 채우기 두 방법 — 0304·0305

| | 0304 Slider | 0305 Filled 이미지 |
|---|---|---|
| 컴포넌트 | `Slider` | `Image` (Type = Filled, Horizontal) |
| 트윈 | `progressSlider.DOValue(목표, 0.8f)` | `frontFill.DOFillAmount(목표, 0.15f)` |
| 글자 갱신 | `.OnUpdate(() => UpdatePercentText(progressSlider.value))` | 즉시 `UpdateText()` |
| 주의 | Slider 는 기본으로 손잡이를 끌어 값을 바꿀 수 있다. 못 끌게 하려면 **Interactable** 을 끈다 | **스프라이트가 있어야** 동작 (`docs/animation/20-gauge-damage-delay.md`) |

`ProgressBarFill.cs` 24–26행

```csharp
fillTween = progressSlider.DOValue(targetValue01, duration)
    .SetEase(Ease.OutQuad)
    .OnUpdate(() => UpdatePercentText(progressSlider.value));
```

`OnUpdate` 는 트윈이 값을 바꿀 때마다 불리는 콜백입니다. `DOTween.To` 의 setter 와 비슷한 일을 합니다.

### 6. 두 겹 게이지 — 0305

[그림: Gauge 안 겹친 순서. 아래부터 Frame → FillBackground → DelayFill(노랑) → FrontFill(빨강) → Flash(흰색 알파 0) → HpText]

`GaugeDamageDelay.cs` `Damage()` 53–73행 (찾을 글자: `// 1. 메인 게이지는 즉시 줄어듦`)

```csharp
// 1. 메인 게이지는 즉시 줄어듦
frontFill.DOFillAmount(target, frontDuration).SetEase(Ease.OutQuad);           // 0.15초

// 2. 잔상 게이지는 잠깐 머물렀다가 천천히 따라옴 → 얼마나 깎였는지 눈에 보임
delayFill.DOFillAmount(target, delayDuration)                                   // 0.5초
    .SetDelay(delayTime)                                                         // 0.4초 뒤
    .SetEase(Ease.InOutQuad);

// 3. 게이지 흔들림
gaugeRoot.DOShakeAnchorPos(0.3f, new Vector2(shakeStrength, shakeStrength * 0.5f), 20, 90f, false, true)
    .OnComplete(() => gaugeRoot.anchoredPosition = originalPos);

// 4. 번쩍임
flashImage.color = new Color(flashImage.color.r, flashImage.color.g, flashImage.color.b, 0.7f);
flashImage.DOFade(0f, 0.25f);
```

| 필드 | 기본값 | 하는 일 |
|---|---|---|
| `maxHp` | 100 | 최대 체력 |
| `frontDuration` | 0.15 | 빨강이 줄어드는 시간 |
| `delayTime` | 0.4 | 노랑이 따라오기 전 기다림 |
| `delayDuration` | 0.5 | 노랑이 따라오는 시간 |
| `shakeStrength` | 12 | 흔들림 세기(px). 세로는 절반 |
| `damageColor` / `healColor` | 노랑 (1, 0.85, 0.3) / 초록 (0.45, 1, 0.55) | 잔상 색 |

**회복은 거꾸로** (`Heal()`, 78–95행): 잔상(초록)을 목표로 **바로** 맞추고, 빨강이 `delayTime * 0.5f`(0.2초) 뒤 0.5초에 걸쳐 따라 찹니다.

**흔들림의 기준 위치**: 흔들기 전 `anchoredPosition = originalPos` 로 맞추고, 끝나면(`OnComplete`) 다시 맞춥니다. 흔들리는 도중 또 맞아도 자리가 밀리지 않습니다.

## 정리

- 바뀐 순간을 알리려면 **펀치**(튀고 돌아옴). 펀치 전에 `DOKill` + 크기 초기화.
- `Insert(시각, 트윈)` 은 시퀀스 안 정해진 시각에 끼워 넣는다. 겹쳐 돌려서 더 빠르고 이어진 느낌.
- 함수가 없는 값은 `DOTween.To(() => 값, v => 값 = v, 목표, 시간)`. setter 에서 글자도 함께 바꾼다.
- 막대는 Slider(`DOValue`) 또는 Filled 이미지(`DOFillAmount`). Filled 는 스프라이트가 있어야 한다.
- 피격 게이지 = 즉시(빨강) + `SetDelay` 잔상(노랑) + 흔들림 + 번쩍임. 회복은 거꾸로.
- 20번 이후 씬은 **빌더 코드**를 고치고 다시 빌드해야 오래 남는다.

## 과제

**과제. 보상 결과 화면** — 새 씬에 아래 네 가지를 놓고, 버튼 하나(**Claim**)로 차례로 보여 준다.
- ① 체크마크 성공(0302 방식) → ② 골드 숫자 카운트업(0303, 천 단위 쉼표) → ③ 경험치 막대 채움(0304, 색 그라디언트) → ④ 뱃지 숫자 +1 펀치(0301)
- 차례는 `DOTween.Sequence()` 의 `AppendCallback` 이나 `AppendInterval` 로 잇는다 (예: `seq.AppendCallback(check.PlaySuccess).AppendInterval(0.5f).AppendCallback(() => countUp.CountTo(1250));`)

| 제출물 | 채점 기준 | 배점 |
|---|---|---|
| 동작 영상 (10초 안쪽) | 네 연출이 정한 순서로 겹치지 않고 나온다 | 30 |
| 스크립트 (`.cs`) | 컴파일 오류 없음. 시퀀스 하나로 순서를 잡았다. 다시 눌러도 처음부터 깨끗하게 다시 나온다 | 30 |
| 숫자 표시 | 카운트업에 쉼표, 막대에 퍼센트 글자 | 15 |
| 시간표 | 각 연출의 시작 시각·길이를 표로 적었다 | 15 |
| 공통 | 파일 이름 `이름_03_번호`, 커밋 메시지 `3차시 과제` | 10 |

## 확인 질문

1. 뱃지에 `DOScale(1.4f, 0.3f)` 대신 `DOPunchScale` 을 쓴 까닭은?
   - **정답**: `DOScale` 은 1.4 에 머물지만, 펀치는 튀었다가 원래 크기로 돌아온다. 숫자가 바뀐 "순간" 만 알리면 되므로 펀치가 맞다.
2. `DOTween.To` 의 두 번째 인자 `value => { currentValue = value; countText.text = … }` 는 언제 불리는가?
   - **정답**: 트윈이 값을 바꿀 때마다(매 프레임) 불리는 setter 다. 그 안에서 글자를 바꿔 숫자가 굴러가 보인다.
3. 20번 게이지에서 노란 잔상이 빨간 게이지보다 늦게 줄어드는 까닭을 코드로 말해 보라.
   - **정답**: 빨강은 `DOFillAmount(target, 0.15f)` 로 바로 줄고, 노랑은 `.SetDelay(0.4f)` 뒤 0.5초에 걸쳐 줄어든다. 두 이미지가 겹쳐 있어 그 사이의 노란 부분이 "깎인 양" 으로 보인다.
